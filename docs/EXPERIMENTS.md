# 实验准备与测量口径

Mac 参考实验环境标记为 desktop-loopback-not-mobile。服务器和客户端位于同一台电脑，共享 CPU、内存及热环境，不构成独立云端算力对照。正式移动实验使用 iPhone 15 Pro Max / iPhone 16 Pro 作为客户端、独立电脑运行服务器，分别记录设备和网络条件。当前完成范围见 HANDOFF.md；下方字段主要针对 Python 参考客户端，iOS 计时差异见 IOS.md。

## 日志字段

- duration_ms：读入文件后，从执行开始至解析最终结果结束。CLI 不包含相机取景、磁盘读图和 GUI 渲染；移动端 UI 计时另行扩展。
- trace：P/O/C/T 各阶段的 location 和 duration_ms。P 包含解码、方向校正、缩放及输出编码。
- request_ms：手机模拟客户端观察的一次完整 HTTP 请求时间，包含网络、服务排队和远程计算，不能再与服务器阶段时间相加当作总时间。
- queue_wait_ms：服务线程内等待推理锁的时间，不包括操作系统接收队列或线程池排队。
- upload_body_bytes/download_body_bytes：应用层 HTTP body 字节数，包括 multipart 表单开销，不包括 HTTP 头、TCP/IP、TLS 开销。
- model：固定模型、预处理和解码标识。端云不一致会失败。
- status/error：成功、无文字和失败；失败保留记录，不混入成功均值，也不能丢弃后只报告成功样本。

## 下一阶段实验顺序

真机批量入口和统计方法见 [BENCHMARK.md](BENCHMARK.md)。2026-11-27 的真实图片试跑发现译文质量问题、生成上限失败以及 S3 的部分 OCR 差异；正式报告必须同时披露，不能把状态 SUCCESS 当成翻译准确。

1. 用固定真实图片校验端云结果与语言质量，建立人工标注。
2. 每种方案独立预热，再进行至少 5—10 次重复，随机或交错执行。
3. 分别改变带宽、RTT、图片大小、文字量及服务器负载，其余条件固定。真实网络整形需验证生效；不以 sleep 冒充带宽控制。
4. 分开建立校准集和评测集，同图派生版本进入同一组。
5. 比较中位数、均值、离散程度、成功率和实际传输量；样本量足够后报告 P95。
6. 在这些数据上建立成本模型，添加动态调度，再与固定方案和简单阈值策略对照。

计时日志默认不保存图片与全文。smoke_report.json 使用工程生成的公开合成文字并保留译文用于验收。用户实际图片不要加入公开提交包。
